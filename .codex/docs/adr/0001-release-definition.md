# ADR 0001 · 1.0 发布定义与范围

- 状态：已接受（2026-10-26）
- 决策者：项目负责人（本轮指令：一路到底，不做市场化取舍）

## 背景

0.15.0 已经有了插件内核、可视化设计器、看板运行态、常驻数据引擎与插件脚手架。
但「什么算做完」一直靠口头描述，导致每个里程碑都能无限加功能。

## 决定

1.0.0 的完成标准是**六条可复现的用户旅程全部闭环**，而不是功能数量：

| ID | 旅程 | 判据 |
|---|---|---|
| T1 | 干净 Windows 装完即用，接串口/仿真，打开看板全屏，重启回到上次看板 | 手工 15 分钟 runbook + 桌面冒烟无错 |
| T2 | 无代码搭多块看板，导入导出往返，未知控件占位不丢 | 看板库用例 + 导入导出用例 |
| T3 | 一句话生成看板，连续增量修改，每轮先看 diff，一次撤销 | 模型 mock + 真桥回路 + patch 用例 |
| T4 | 插件放进扩展目录即可安装、看权限、授权、停用回收 | 装机版冒烟 + 授权用例 |
| T5 | 20 通道 @100Hz 长跑稳定，算子参数可调 | 性能基准 + 长跑诊断 |
| T6 | 一条命令完成发布门禁并产出可回滚安装包 | release 脚本 + verify-dist |

## 非目标（1.0 不做）

插件市场、代码签名/PKI、iframe/Worker 沙箱、实时管线分支合并、多窗口、云同步、
自动更新、看板轮播、zip 插件包导入。

## 后果

- 任何「新功能」必须先回答：它服务哪条旅程？答不上就进 1.1 待办。
- 权限是**能力投影**，不是安全沙箱；文档必须反复说清楚，避免用户误以为装了插件就安全。
