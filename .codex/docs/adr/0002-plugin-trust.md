# ADR 0002 · 插件信任模型与存储位置

- 状态：已接受（2026-10-26）

## 背景

插件目前只能放在源码目录 `plugins/`。装机版跑的是 `app.asar`，用户无法往里加文件 ——
「插件化框架」在安装形态上还不成立。

## 决定

1. **用户扩展目录**：`%APPDATA%\XiHe GCS PRO\extensions\<id>\`；首启自动创建。
   静态服务新增 `/ext` 路由（仍做 canonical path 检查），内置 `plugins/` 与用户目录同时发现。
2. **授权模型**：`granted = manifest.permissions ∩ 用户同意`。
   首次启用弹权限清单；`network / fs:own / data:write` 默认不勾选；
   版本或代码指纹变化时重新确认。未授权的能力在 `ctx.api` 上不存在（沿用现有投影机制）。
3. **停用状态持久化**：`xhgcs.ext.state.v1`，重启后保持停用。
4. **信任边界**：明确「权限是能力投影，不是沙箱」。只装可信插件；
   签名、市场、iframe 隔离不在 1.0 范围（见 ADR 0001）。
5. **路径安全**：插件入口必须是插件目录内的相对路径；拒绝跨源、绝对路径、`..` 与目录外符号链接。
6. **内建信任**：`xihe.core` 与随包示例插件自动授权，不弹窗。

## 后果

- 安装包体积增加很小（只是多一条路由与一次目录创建）。
- 企业分发如需签名，可自行用 electron-builder 证书签名；1.0 安装包未签名，Windows SmartScreen 会提示，
  发布说明必须写明。
- 撤销权限后必须立即回收贡献点（沿用 `registry.unregisterAll(owner)`）。
